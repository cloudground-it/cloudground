# v0.3.1 release candidate on the purged box

2026-10-12, the same OVH VPS as [v0.3.0-rc.md](./v0.3.0-rc.md) (Ubuntu 26.04, 2 vCPU "Intel Core
Processor (Haswell, no TSX)", 4 GB; CPU parity 2.09–2.29 s through the run, 0 % steal). The
candidate is main at **e1ff3cc** (`v0.3.0-4-ge1ff3cc`): the panel's new visual design (#131), the
new-site wizard (#133), its aliases and DNS check (#134), and #135, which fixed the wizard's one
`nuxt typecheck` error (a `close` prop key the type does not have; Nuxt UI labels the button from
the panel's locale). It was built with `make docker-dist`, `make docker-e2e-bin` and
`make docker-upgrade-bundle`. The changes are in the panel's UI and one read-only API route, so
this run checks that nothing else moved.

## Update from the v0.3.0 release

The box ran v0.3.0 as installed by `get.cloudground.it`, with an admin and the bench site of
`setup-workload.sh`. A self-update takes only a release signed with the real key from the real
feed (`cgctl update --check` said `up to date: v0.3.0 is installed`), so the candidate went on
through the development path, `CLOUDGROUND_LOCAL_BUILD=dist bash installer/install.sh`, over the
installed release (`--from` is not checked against it, internal/install/SPEC.md §5 step 3a). The
signed update itself, with its guard, snapshot and rollback, is `R-6.5 upgrade` below.

The run took 0m 5s and said `The panel was already set up: sign in as before`. Afterwards:
the three binaries report `v0.3.0-4-ge1ff3cc`; the agent, the API and nginx are active;
`cgctl doctor` reports `no drift`; the admin signs in on port 8443; the bench site is still
listed, `active`, and serves its shop page (200); `/sites/new` (the wizard) and `/healthz`
answer 200; and `GET /api/sites/dns-check?domain=<the bench site>` answers `"status":"here"`
with the server's own address marked `own`.

## Install and the full e2e

`cgctl uninstall --remove-sites --purge-packages` removed CloudGround but purged nothing: the
data-plane packages were on the box before the v0.3.0 install (put back after the v0.3.0 run's
cleanup), so that install recorded none, as SPEC §8 says. They were purged by hand, which took the
box back to stock Ubuntu.

The clean install took **0m 55s** (v0.3.0 candidate: 0m 49s). Then the full suite ran
sequentially with `CG_E2E_UPGRADE_BUNDLE`: **1599 passed, 0 failed**, 59 sections, 45m 15s.
Every section passed. Against the v0.3.0 candidate's 1584, two sections grew:

| Section | v0.3.0 candidate | this candidate | What was added |
| --- | ---: | ---: | --- |
| R-6.1 installer | 43 | 51 | #128 (in v0.3.0, merged after its candidate run): needrestart leaves the agent's transient units alone |
| F9b site creation | 33 | 40 | #132: the DNS check (a name pointing here, the server's address listed, a name pointing elsewhere, an address refused) and a site created with an alias (accepted, stored, served by nginx) |

The driver ran as a transient unit that needrestart was told to leave alone, as in the v0.3.0
run; no run was restarted this time.

**Reading:** there is no regression, as expected of a release that changes only the panel's UI
and adds one read-only route. The two drops (−0.6 % and −0.2 %) are far inside the candidate's own
spread (7.7 % and 10.5 %). The gains are not credited to the release either: nothing on the
request path changed, and the candidate ran second, on a site that had been warm for 15 minutes.
The uncached gain is the largest and also the noisiest (16.9 % spread between the candidate's
runs). No scenario had an error except the flood's expected refused connections (987 a run); the
candidate's third flood also had 495 timeouts, which the flood's ±20 % on this box covers
(README). These means are below the v0.3.0 candidate's record of the morning (9,661 on
cached-sustained); that is the box, which is why the two builds were compared in one sitting.

After the run the box was taken back to stock Ubuntu: `cgctl uninstall --remove-sites
--purge-packages`, then ClamAV purged by hand (the malware scan's sections install it; the
installer does not record it), and the test files removed.
